# 流水线结果可视化实施计划

日期：2026-10-21  
状态：P1、P2、P3 和 P5 已实现；P4 已接入现有样例覆盖的报告格式，未覆盖的分型工具继续保留下载；P6 继续进行界面与联调验证。  
接口依据：[流水线结果展示接入说明](./pipeline-results-visualization-guide.md)。

本计划覆盖病毒流水线 `100/101` 和常规细菌流水线 `200` 的已有结果读取、展示和文件下载。先交付结构化结果，再适配报告文件；不调整分析算法、任务创建或上传流程。采用独立的单任务结果页，内部按阶段切换展示，不为每个阶段新增独立页面，也不重做跨任务结果中心。

## 交付顺序

| 阶段 | 工作内容 | 可验收交付物 |
| --- | --- | --- |
| P1 | 结果契约、文件读取、局部错误处理 | 能正确取得阶段结果和单个报告，解析失败不影响其他阶段 |
| P2 | 独立结果页、下载列表、输入信息、内联结果 | 能从任务详情进入结果页并定位阶段，查看内联结果和下载文件 |
| P3 | 三类指标 JSON 可视化 | 比对、变异、一致性序列的摘要、表格和必要图表 |
| P4 | QC 与小型文本报告适配 | 对已核实格式的报告提供摘要或明细表 |
| P5 | 真实物种确认交互 | 提交、刷新，以及确认已保存但调度失败的恢复处理 |
| P6 | 综合联调与验收 | 已实施范围的测试记录和未完成项清单 |

P1 → P2 → P3 是第一批只读结果 MVP，附带这些阶段的回归验证即可先交付。P4 按实际样例逐项推进；P5 在 P2 后可独立开展，但在它通过验收前不开放正式确认操作。P6 汇总验收，不代替每个阶段自己的测试。

## 已确认的页面设计

- **任务详情页**：保留任务信息、运行状态、workflow 和待处理事项提示，提供“查看结果”入口。原有节点点击选中行为保留，在选中阶段处提供“查看阶段结果”入口。
- **任务结果页**：独立页面，左侧为阶段导航，右侧为当前阶段结果。可查看已产出结果，不要求整条流水线已完成；等待、失败和不适用阶段仍有相应状态说明。
- **阶段结果组件**：按结果类型拆分摘要、表格、图表及下载展示，由结果页统一承载。不为每个阶段建一个页面，也不把所有展示逻辑堆在一个 Vue 文件中。

页面跳转只传 `pipelineId` 和可选 `stageId`。结果页自行加载任务和完整阶段列表，不依赖详情页传递结果对象或保留其组件实例。传入有效 `stageId` 时定位该阶段；未传时优先选择按展示顺序排列的首个已有结果阶段，没有结果则显示当前任务状态。传入的阶段不存在时提示并回到默认选择，不留下空白内容。

导航复用 `App.vue` 现有的页面切换和事件机制，新增 `task-results` 页面键，不为此引入新路由库。App 使用响应式状态保存跳转 ID，并分别保存详情页原来源与结果页返回上下文。结果页返回同一任务详情，详情再返回原来源页面（通常是任务列表），不能直接沿用当前单个 `previousPage` 导致跳错页或来回循环；同时补齐页面标题和任务菜单高亮。

P5 的确认操作统一放在结果页的分类模块；详情页的待处理提示定位到该模块，不维护两套确认表单。尚未接入真实确认接口时，两处都不触发模拟成功逻辑。

## P1 结果读取基础

### 实施内容

- [x] 复用现有 Axios 请求封装和 API 基础地址，不新增另一套请求方式。
- [x] 完整阶段详情继续使用 `GET /pipeline/getPipelineStages`；状态查询结果不覆盖完整 `outputInline`。
- [x] 补充参考选择 `stageType=44`，明确接口状态、流水线状态、阶段状态、分类结果状态各自的含义。
- [x] 在 API 到前端模型的转换处统一解析 `outputInline`、`outputUrl`，组件不重复解析。
- [x] 逐阶段、逐结果字段处理空值和坏 JSON，保留错误信息。某个字段解析失败时，其他可用字段及其他阶段仍可展示。
- [x] 提供报告文本读取、JSON 解析和文件下载能力。请求 `/stageOutput/download` 时只传单个文件对象键，通过 Axios `params` 编码一次。
- [x] 区分业务响应和文件响应：前者检查业务 `status`，后者直接读取内容；沿用现有拦截器，不重复解包 `.data`。
- [x] 为结果模块分别维护加载、成功、暂无结果和失败状态，提供局部重试；未定义的指标不填零。
- [x] 结果文件按需读取。同一模块避免重复在途请求，切换任务或阶段后旧响应不能覆盖当前结果。
- [x] 阶段状态不变但输出更新时，也更新展示数据。若使用缓存，刷新结果和文件对象键变化时使对应缓存失效。
- [x] 保留空开始/结束时间，避免 `new Date(null)` 变成 1970；只有有效起止时间才能显示最终耗时。

历史兼容集中在适配处处理：参考选择允许 inline 为空时回退旧 urls；VF 旧 `amrTsv` 仅在 VF 阶段使用。旧 `qcUrl` 或内联 `metrics/qcMetrics` 需要先核实实际快照形状再适配；没有样例时明确显示旧记录未提供可识别指标，不猜测结构。

### 验收条件

- [x] HTTP 200 的业务失败、网络失败、文件接口的非 JSON 错误体均能正确提示。
- [x] 空串、null、坏 JSON、合法的数值零有不同处理；坏 JSON 不导致整页结果消失。
- [x] 对象键含空格、中文、`&` 等字符时，实际请求参数仍是原始单个键。
- [x] 切换任务、切换阶段、重试和同状态刷新不会出现旧结果覆盖新结果。

## P2 独立结果页与基础展示

### 页面接入

- [x] 新增单任务结果页，由 `pipelineId` 驱动加载，支持可选 `stageId` 定位。
- [x] 接通任务详情的“查看结果”和选中阶段的“查看阶段结果”入口，不改变 workflow 节点原有选中行为。
- [x] 结果页采用左侧阶段导航、右侧内容区；阶段列表以接口实际返回为准，不直接用 `stageIndex` 排序。
- [x] 提供页面初次加载、整体请求失败重试、无阶段空态；已加载后的报告错误保留在对应模块内。
- [x] 同一结果页切换不同任务时重置旧选择和数据，并重新加载，不能只依赖首次挂载。
- [x] 接通返回同一任务详情、页面标题和任务菜单高亮，不替换现有跨任务 `ResultsView.vue` 示例页面。

### 结构化结果模块

- [x] **输入检查**：从 `readMeta` 展示平台、长短读、质量编码和序列层级。根据规范化 R1/R2 展示输入布局；未知编码保留原值，不根据读长推断平台。
- [x] **参考选择**：展示 `selectedReference` 及序列表、`candidateScores` 候选表、未匹配节段和补充检查状态。选中标记按 accession 关联，节段按数值顺序展示；不按数组下标关联。
- [x] **物种分类**：展示 `best`、候选、证据来源和已有人工确认记录。响应字段使用 `taxid`，不强行给空 `best` 填第一名；分数标签依据证据来源解释。
- [x] **分箱信息**：展示 `binningMetrics` 的摘要、分箱表和碱基组成堆叠条。保留未解析到物种及未分类部分；原始优势分箱与人工确认结果分开呈现。
- [x] **阶段状态**：保留执行失败、等待处理、不适用、完成但无结果的区别。OUT_PANEL 的已有分类证据仍展示；没有跳过原因时不自行推断原因。

参考选择的 `partial`、`selectedReference.complete` 和 `compositionStatus` 不转换成样本完整度、缺节段或混样结论。分类分箱组成不标为样本物种丰度。

### 验收条件

- [x] 仅传 `pipelineId` 即可独立打开结果页；传 `stageId` 可正确定位，阶段不存在有明确提示和回退。
- [x] 任务未完成时可查看已有结果；从结果页返回的是同一任务，继续返回可到详情原来源页面。
- [x] 阶段 `44` 的 inline-only 结果不会因 `urls=null` 报错；输入检查 `80` 可见。
- [x] R2、Scaffolds、原始 VCF 索引和 K/O 报告为空时无无效下载按钮。
- [x] taxonomy inline 内的文件可以下载，`readMeta` 等对象不会成为文件项。
- [x] 阶段 `6` 仍显示已有证据或不适用原因；未创建的阶段不补成失败。
- [x] 在真实确认接口接入前，候选只读展示或明确禁用确认，不触发原有模拟成功逻辑。

## P3 指标 JSON 可视化

三个模块均从各阶段的 `metricsUrl` 读取指标。先完成指标表和单位，再添加用于比较的图表；图表与表格共用同一份解析结果。

| 模块 | 摘要 | 表格与图表 | 验收重点 |
| --- | --- | --- | --- |
| 比对 | 比对率、至少 1× 覆盖率、平均/最高深度、参考长度 | `references[]` 明细表；按参考分别比较覆盖率和深度，不混用数值轴单位 | 总体使用顶层统计；不对各参考平均深度再简单平均；read segments 不叫 read pairs |
| 变异 | 变异记录总数、SNP/INDEL/其他计数 | 变异类型分布、过滤状态分布分开展示；分参考明细表 | `totalVcfRecords` 不当变异总数；未过滤不等于 PASS；已标记过滤不叫已删除 |
| 一致性序列 | 深度遮罩阈值、遮罩/未遮罩位置数与比例 | 总体遮罩堆叠条；`sequences[]` 明细表 | 统计基于参考坐标；不标为最终 FASTA 长度、N 数或基因组完整率 |

- [x] Fraction 乘 100；参考选择 `sequenceIdentity` 已是百分数，不再次乘 100。
- [x] 深度显示 `×`，长度显示 `bp`，数量明确记录单位；空值与零值不混用。
- [x] 比对指标的 `referenceName` 不保证等于 accession，未确认映射时按原标识展示，不凭数组顺序附加节段名。
- [x] 零条变异等合法零结果正确显示，图表不出现除零或 NaN。
- [x] 单个 metrics 请求失败可单独重试，不影响同阶段文件下载和其他模块。
- [x] 不自动加载深度 TSV、VCF、FASTA 或 BAM 来补齐文档没有提供的指标。

第一批只读 MVP 到此具备内联结果、三个指标模块及全部已发布文件入口。尚未适配的报告明细保留下载，不伪造统计。

## P4 QC 与文本报告适配

实施每个适配器前先取得该格式的真实脱敏样例，至少核实字段、单位、空结果表现。样例缺失只影响对应格式的结构化展示，不阻塞其他模块和文件下载。

已依据 [后端报告样例说明](./pipeline-report-examples.md) 只读核实 9 份 WSL 真实工具产物，脱敏回归夹具保存于 [report-fixtures](./test-data/report-fixtures/README.md)。当前支持 fastp 1.0.1、fastplong 0.4.1 样例中的 QC 摘要，AMRFinder、ABRicate、无表头 MLST，以及按主要表头识别的 ECTyper 报告。Kaptive、SeqSero2、SeroBA、pFaster 尚无样例，不套用 ECTyper 解析。

| 优先顺序 | 报告 | 处理内容 | 交付展示 |
| --- | --- | --- | --- |
| 1 | QC `reportJSON` | 按实际工具区分短读和长读报告；核实过滤前后统计、质量值和过滤原因 | 指标卡、前后对比条形图、过滤原因表/图；仅展示实际存在字段 |
| 2 | AMR / VF TSV | 按真实表头读取；保留有意义的原始列，不把文件键当结果列表 | 可筛选的注释命中表；统计仅建立在已确认字段上 |
| 3 | MLST 报告 | 提取实际格式中的 scheme、ST 和等位基因结果，不假定所有版本有相同表头 | 摘要卡及等位基因表 |
| 4 | 血清分型 TXT/TSV | 分工具适配；先确认如何从文件结构或明确元信息识别格式，不能只看扩展名 | 已识别格式的结果摘要与表格；不识别时保留下载和提示 |

### 验收条件

- [x] QC 缺少 Q30 等字段时显示未提供，不填零；长读报告不强套短读字段。
- [x] 文本解析覆盖 BOM、CRLF、空行、缺字段和合法空报告；是否有表头依据具体格式确定。
- [x] 有表头无数据行只有在该报告规范允许时，才解释为无匹配记录。
- [x] AMR/VF 展示注释命中，不生成药敏或致病性结论；MLST 不替代物种鉴定结论。
- [x] HTML 仅作附件下载，报告文本不直接用 `v-html` 注入页面。
- [x] 超出适合前端处理范围的文件保留下载，另列后端解析需求，不阻塞渲染线程加载全部明细。

报告仅在选中已完成阶段时读取，使用生产文件对象键，不使用样例的本地路径。预览上限为 5 MiB，文本报告最多 10000 行、256 列；表格搜索后按页渲染，超限不截断成完整结果。XHR 进度检查用于尽早取消超限请求，响应后另检查 UTF-8 字节数；这是展示限制，不是严格的传输内存上限。大报告解析与分页仍需后端支持，原文件下载不受预览限制。

## P5 物种确认真实接口

这是已有交互的协议修正，不把人工确认功能藏在只读可视化适配中一起修改。依赖 P1 和 P2，独立验证后再开放。

- [x] 替换模拟确认请求及强制修改响应为成功的代码，接入 `POST /pipeline/stage/taxonomy/confirm`。
- [x] 首次确认只在流水线运行中且阶段等待处理时开放，只能选已有候选。提交 `stageId`、候选 `taxid` 对应的 `taxId`、可选 `reason`。
- [x] 禁止提交候选之外的 TaxID；原因最多 2000 字符，不提交前端构造的版本或确认人。
- [x] 请求中禁止重复点击。响应后刷新完整详情，不在前端直接把阶段和分类结果改成成功。
- [x] HTTP 错误处理中保留后端携带的确认数据；区分“未确认成功”和“确认已保存，但下游启动失败”。
- [x] 对后者提供单独的恢复操作，重复相同确认请求，不允许借此更换候选；是否可恢复以服务端响应为准。
- [x] 展示后端 `manualConfirmation` 审计信息；刷新后保留原始分箱结果，不假定它已因确认而重算。

### 验收条件

- [x] 正常确认、业务拒绝、网络失败均不产生本地假成功。
- [x] HTTP 500 携带 `downstreamScheduled=false` 时能说明已保存并重试调度。
- [x] 确认请求返回不确定时刷新详情核实，不直接允许选择另一个候选。
- [x] OUT_PANEL 不开放普通确认；同一确认的调度恢复与首次确认的入口和状态条件分开。

## P6 综合联调与回归

### 场景矩阵

- [ ] 病毒 Reads、病毒 Assembly、细菌 Reads、细菌 Assembly 按实际阶段列表展示，不使用固定阶段数量判断成功。
- [ ] 单条参考、多条参考、缺少可选报告及新旧结果字段分别验证。
- [ ] 部分阶段已完成、其他阶段运行或失败时，已完成结果仍能独立查看。
- [ ] 分类已确定、歧义、证据不足、超出范围及人工确认记录分别验证。
- [ ] 结果 JSON 错误、报告文件不存在、服务端 5xx、超时、未知格式和合法空结果分别验证。
- [ ] 快速切换任务、阶段，连续刷新和局部重试不会串数据或重复积累候选项。
- [ ] 首次打开结果只加载所需元信息和指标；大型原始文件不自动下载。

### 验证方式
