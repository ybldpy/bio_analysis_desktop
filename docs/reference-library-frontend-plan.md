# 参考序列库管理前端实施计划

创建日期：2026-10-23；更新日期：2026-10-24。  
状态：P1 至 P4、P6 至 P8 已实现，P5、P9 的自动测试、定向类型检查与构建通过；图形界面及真实后端联调仍待验收。  
接口依据：[专项入口前端交接说明](./reference-library-frontend-handoff.md)及[参考序列库管理说明](./reference-library-management-guide.md)。

在独立参考序列库管理页面上增加病毒专项入口、专项上传与归属确认、参考文件下载。页面管理全局候选资格，不为单次任务指定参考，不改变已有参考快照或分析算法；任务白名单另列后续范围。

本计划采用 2026-10-24 最新确认的交互：专项内上传不让用户填写 Tax ID，而是由前端提交 `taxId=targetTaxId=所选专项.taxId`。此规则覆盖交接说明中专项上传手填实际 taxId 的旧要求；无专项的全局上传仍填写实际 taxId。类别编码以新版交接说明的 `0=病毒、1=细菌` 为准，不能继续采用旧管理说明的 `1=病毒、2=细菌`。

## 实施顺序

| 阶段 | 内容 | 验收结果 |
| --- | --- | --- |
| P1 | 独立类型与 API 封装 | 四个新接口、业务错误、HTTP 错误与 multipart 参数正确 |
| P2 | 管理页面和导航 | 精确筛选、服务端分页、刷新、空态和错误重试 |
| P3 | 详情与逐条启停 | 按 ID 加载详情，开关以服务端响应为准，失败重新核实 |
| P4 | 上传追加与异常恢复 | 单文件、元数据校验、发送进度和服务端处理状态、提交待确认提示 |
| P5 | 回归验证与交付 | 自动测试、生产构建和人工联调清单 |
| P6 | 类别编码与专项入口适配 | 病毒管理固定传 0，专项范围查询受部署确认开关控制 |

- 顶部明确提示全局启停影响后续候选加载，已有任务快照不追溯改变；实际参考仍由流水线选择。

## P1 接口契约

- [x] 接入 query、详情、upload、enabled 四个管理接口，不修改或调用旧参考列表接口。
- [x] 正确处理 `status=0/1/2/3/4`，失败 `data=null`、`failMsg=null` 及 HTTP 非 JSON 错误。
- [x] HTTP 错误仍拒绝 Promise，保留响应体提示；HTTP 200 单独检查业务状态。
- [x] 分页参数 `start=(page-1)*pageSize`，每页最多 100 条；保留明确传入的 `enabled=false`。
- [x] 上传使用 `file` 和独立表单字段；数字及布尔值转字符串，空可选字段省略，不手动设置 multipart Content-Type。
- [x] 查询支持取消；上传不自动重试，不把超时或取消解释成服务端已回滚。

## P2 列表与筛选

- [x] Tax ID 正整数精确查询，状态默认全部，accession 去首尾空格后精确查询。首版类别选择由 P6 的病毒固定类别替换。
- [x] 不提供后端尚未支持的名称模糊搜索或前端排序；专项成员范围的查询列入 P6。
- [x] 筛选提交后回到第一页；翻页采用服务器返回总数，不用当前页记录推算全库状态。
- [x] 列表展示名称、Tax ID、accession、来源、长度、节段和启用状态；空元数据展示未提供。
- [x] 页码越界时回到最后有效页重新查询；零条结果回到第一页。限制单次自动纠正次数，避免数据持续变化导致无限请求。
- [x] 新查询使旧查询失效，卸载取消读取；旧响应和旧 finally 不能覆盖新数据或加载状态。
- [x] 初次加载失败显示重试，刷新失败保留已加载结果并标明失败，不能误报为空库。P6 切换专项时需清空旧专项数据，不沿用这一保留策略。

## P3 详情与启停

- [x] 打开详情调用按 ID 查询接口，不依赖旧列表行作为最新详情；切换记录防止响应乱序。
- [x] 只读展示已发布字段；对象键不直接作为链接，空键显示“文件位置不可用”。通过文件接口下载的能力列入 P8。
- [x] 开关文案为“允许作为分析候选”；逐行 loading、防止重复请求，不提供批量保存。
- [x] 操作成功后以服务端返回对象更新行及打开的详情；当前筛选不再匹配时重新分页查询。
- [x] 操作失败保留服务端上次状态并重新查询核实；恢复查询也失败时保留错误提示，禁止宣称操作成功。
- [x] 不阻止禁用最后一条，不根据当前页作全库判断；管理页全局启停不用于保存单次任务的参考选择。

## P4 上传与异常恢复

- [x] 一次选择一份 FASTA 或支持的压缩文件，再次选择可替换；一份文件对应一条库记录。
- [x] 首版具备文件和分类元数据校验，以及可选 accession、分类名称、节段、完整性文本；默认启用。用户输入项按 P7 的两种上传模式调整。
- [x] 前端检查非空文件、扩展名、默认 256 MiB 上限及元数据格式/长度，不在浏览器解析全部序列或推断分类。部署调整上限时同步前端常量，最终以后端限制为准。
- [x] 提示 ZIP 应只有一个文件、解压后也有大小上限、元数据由用户声明，不将格式检查标为质量结论。
- [x] 提交期间锁定表单和关闭按钮、防止双击；发送 100% 后显示“服务端校验并导入中”，只有成功响应才显示完成。
- [x] 成功后清理表单、刷新列表并可查看新增记录详情，不盲目把不符合当前筛选的行塞入列表。
- [x] 校验失败和重复 accession 保留表单，提供普通文本错误；重复时可按 accession 查询已有记录。
- [x] 内部错误、断线、超时和未知响应不自动重传；显示可能已提交的提示，优先按 accession 核实。
- [x] 按 accession 核实时清除 Tax ID、类别、状态等残留过滤；未收到服务端生成标识时可查看近期记录，由用户确认后主动决定是否重新提交。
- [x] 不依赖从中文错误消息解析出可靠机器字段；可展示原提示并允许用户复制或填写其中的标识。

上传中和结果待核实时阻止应用内导航离开管理页。关闭弹窗仍保留表单，完成查询核实后可明确解锁手动重传，或确认结束本次上传并清空本地表单；两者均不自动发起上传，也不撤销服务端记录。本期不提供重启应用后的待核实状态持久化。

## P7 专项上传简化与归属确认

### 两种上传模式

专项内上传展示当前专项名称，不提供 Tax ID 输入或选择控件，由前端代填下表字段。后端仍要求 `taxId`，不能从请求中删掉它。这是新增记录的分类赋值规则，不是自动鉴定分类，也不修改已有参考记录。

| 请求字段 | 专项内上传的提交值 |
| --- | --- |
| `targetTaxId` | 所选专项的 `taxId` |
| `taxId` | 同一个专项的 `taxId` |
| `pipelineType` | 所选专项的 `pipelineType` |
| `orgType` | 固定 `0` |
| `confirmAddTaxonomyMember` | 首次省略或传 `false`；明确确认后才传 `true` |

- [x] 专项上下文取后端下发的同一选项，不能混用两个专项的字段；遵循 `100/101` 及新冠目标组合的接口限制。
- [x] 若保留无专项全局上传入口，单独标明上传范围，要求用户填写实际 `taxId`，固定 `orgType=0`；不提交专项上下文，不允许 `confirmAddTaxonomyMember=true`。
- [x] 两种模式继续使用 `multipart/form-data`：文件字段 `file`，其他字段独立追加，数值和布尔转字符串；不手动设置 multipart Content-Type，其余文件与元数据约束不变。

### 归属确认流程

- [x] 首次只提交普通上传，不预先默认同意扩大专项范围。
- [x] 仅在返回 `code === 'REFERENCE_TARGET_MEMBERSHIP_CONFIRMATION_REQUIRED'` 的确认分支处理关联；按协议检查 `status=1`、`data=null`，并核对 `confirmation` 的 `targetTaxId`、`pipelineType`、`taxId` 与当前提交上下文一致。
- [x] 保留表单、文件及提交上下文快照；不通过 `failMsg` 模糊匹配设置确认标志，不把任意 `status=1` 失败当作归属确认。
- [x] 展示以下影响提示，说明扩大的是整个分类范围，不只是关联本次文件；同一目标 taxId 的其他专项选项也可能受影响。

> 此操作会将该分类下的已有及后续参考纳入当前专项范围，实际参与分析仍受启用状态控制。是否继续？

- [x] 用户明确同意后，保留原字段和文件，只增加 `confirmAddTaxonomyMember=true` 重新提交；取消不重提，不默认新增关联。
- [x] 更换专项后清除旧确认标志、待确认快照和弹窗。再次提交从未确认状态开始，晚到响应不得恢复旧授权。
- [x] 归属确认与“上传提交结果待核实”分开处理：前者需要用户授权扩大范围，后者不能自动重传；普通成功、重复、参数错误不要求携带 `code/confirmation`。
- [x] 成功后刷新对应专项列表；新记录不符合当前筛选时仍明确提示成功并提供详情，不把不可见解释成导入失败。

## P8 参考下载与全局结果核实

- [x] 列表或详情提供下载入口，调用现有 `GET /stageOutput/download`，通过 `outputUrl` 参数传递 `fastaObjectName` 并编码一次；复用当前 API 地址和会话配置，不直接链接对象键或拼接服务器路径。
- [x] 对象键为空时不提供可用下载操作；文件不存在、HTTP 错误、JSON／HTML 错误响应明确提示，不保存成 FASTA。
- [x] 下载按保存后的 FASTA 命名，不承诺还原上传时的 gzip／ZIP 包装；不把文件响应当业务 `Result` 解包。
- [x] 重复 accession 和提交结果待核实时使用独立的全局精确查询，清除 `targetTaxId`、`pipelineType`、`orgType`、实际 `taxId` 和 `enabled` 等限制，避免漏掉已保存记录。
- [x] 没收到自动生成标识时允许核对近期记录，不自动换 accession 或重传。此核实路径必须明确标识为全局查询，不冒充当前专项列表，也不用于正常专项查询失败的降级。

## 单次任务参考白名单后续范围

`enabledReferenceIds` 与本次参考库管理改造分开排期，不因增加专项管理而自动修改任务创建流程。后续接入时：

- 不传或传 `null` 使用默认候选；用户显式选择时提交非空、无重复的正整数 ID 数组，不能删掉无效项后悄悄回退默认范围。
- 单个创建放在 `pipelineStageParameters.enabledReferenceIds`；批量放在各项 `pipelines[i].pipelineParameters.enabledReferenceIds`，不调用全局启停接口保存任务勾选。
- 自定义候选查询只带专项上下文、`enabled=true` 和分页，读取全部分页；不继承管理页的 `orgType=0`、实际 taxId 或 accession 筛选，不把当前页选择当作完整候选集合。
- 仅用于 `100/101`，保留创建和启动时的后端校验；已有 Stage 快照不被改写。

## 本期不做

不做编辑序列、覆盖、物理删除、注释上传、原子批量启停、成员级开关、独立成员维护页面、专项创建／删除／改名、细菌参考管理页面、工具数据库重建或新鉴权体系。成员范围由后端展开，专项上传的关联调整只在明确确认后进行。管理入口仅用于受控环境；隐藏前端按钮不构成访问控制。
